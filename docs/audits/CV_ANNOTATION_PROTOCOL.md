## 1. 来源与划分

- 每场原始比赛给唯一 `source_match_id`，不同剪辑、转码、相邻帧、慢动作回放都继承同一比赛编号。
- 保存原视频路径、SHA-256、分辨率、实际解码帧号/PTS、fps、标注人和审核状态。
- train/validation/independent_test 按比赛编号互斥；不能按帧随机划分，也不能把同场比赛的不同文件当独立来源。
- 已经用来诊断、调阈值、试训的来源标 development；不能随后改名 independent_test。
- 四段 `match_testset_20261011.json` 已参与过历史开发；11张审核纠错帧同样是开发子集。当前没有新独立测试来源可证明泛化。
- 近似投篮时间、ordinal结果、切到片段后的相对秒、原片秒、真实过筐时刻分别记录，不互相替代。
- Windows 路径迁移只建立新本地映射清单并核对原 SHA；不修改原始真值，不用“名称像”替换原片。转码/剪辑需另外记录父视频哈希与时间映射。

## 2. 复用现有标注，明确完整性

### 篮球/篮圈/人员帧

复用现有 `annotations.json.frames[].boxes`（kind、xyxy）和 `visibility`；坐标统一为**原始画面归一化 xyxy**，不使用模型 letterbox 或放大 ROI 坐标。扩展人员角色、篮圈细节前先让现有标注器/校验器显式支持新字段，不能假称已有工具能导入全部新类型。

- basketball：所有可见比赛用球；真实模糊球按可见包络框；可见/不可见/看不清/被遮挡分开。看不清帧不作为负例。
- rim：标**篮圈开口区域**；篮板、篮网分别标种类和粗框，不能把篮网大框直接当篮圈口。保留同镜头多篮筐的身份，不猜被遮挡边界。
- person：完整标当前可见人员框，脚点能否判断、遮挡、出界状态；场内球员、裁判、观众、未知分别审核。
- decoy：复用现有纠错框，并用 conditions 标 `head_decoy`、`logo_decoy`、`scoreboard_decoy` 等；一帧同时有真球和假目标时两者都标。
- 每张帧声明 `frame_complete`；球框完整、人员框完整、负例完整性应分别记录。只有局部纠错不能用来计算整帧 Precision，也不能把未圈出的其它目标当背景训练。
- 只有人工确认“没有可见比赛球”的完整帧才是球检测负例；模型没检到不等于没有球。
- 训练用纠错仍要求 `review_status=approved`、`frame_complete=true`、`training_approved=true`、比赛来源ID与图像哈希。审核、标注和模型评估分开保存。

### 连续轨迹与身份

- 从原视频连续窗口密集标注（建议原始帧率）；标真实球身份、DETECTED可见/遮挡区间、切镜边界。
- 每条人员轨迹有临时 track_id、人工球员身份、球队身份、号码可读性，各字段允许 UNKNOWN。
- 脚点不在画面或被遮挡时写不可判；不能强制按框中心判断场内。
- 跨镜头同球员身份需衣号/人工证据确认；没有证据就分段，不根据 tracker ID 或位置近强行合并。

### 逐次投篮

继续复用现有 `shots_truth.csv`、match_testset shots 与 `jersey_split1.template.json`；新增字段应与现有解析器兼容或单独旁表关联。

- event_id、play_id、原片 release_s（或明确近似区间）、rim_s、结果 made/missed/unknown。
- shooter_track_id、shooter_identity、team、jersey_number，未知就留空；模型给出的 shooter 不是真值。
- shot_type：普通投篮/罚球/上篮/扣篮/补篮/未知；分值1/2/3/未知。
- replay标记及对应原始play_id；一次投篮的多次回放不算多次出手。
- 同一篮下争抢的首次出手、补篮分开标，不按时间接近直接合并。
- `shots_complete=true` 仅在整个指定时间窗口逐次看完后勾选；空列表未确认完整不能当“零出手”。

### 记分牌

复用 `scoreboard_split1.template.json`；原始屏幕左右/上下队顺序和真实球队映射分开。

- 密集标比分 old/new、两个数值的可读性、出现时间；若更新有延迟，标真实过筐到比分更新的间隔。
- 记录正常比赛/回放/特写/暂停/广告/未知以及切镜。
- +1/+2/+3 是得分变化真值，不自动等于一次投篮；罚球、多次罚球合并更新、技术罚球、比分纠正单独标。
- 得分确认但出手不在画面/球员不明，记录得分事实并留未知归属，不编轨迹和投篮位置。

下一批先覆盖下面18个场景，各提供一个完整连续窗口；建议每种至少3个窗口以观察失败类型，这只是采集起点，**不是足够证明总体精度的样本量**。

1. 远景小球：保留小于12px的真实球，框完整性单独审核。
2. 快速传球：逐帧球位置及传球双方；不能标为投篮。
3. 三分投篮：脚点、出手、筐、结果和真实分值。
4. 上篮：遮挡、近筐离手与过筐分别标。
5. 扣篮：上升准备、向下穿筐、手/球重叠。
6. 补篮：与前次出手不同event_id、同play_id。
7. 明确未中：打铁/偏筐/篮板证据。
8. 篮球遮挡：最后可见与再次可见的真实时刻，不给不可见帧编球框。
9. 看台干扰：运动/静止人头与真球同时出现。
10. Logo干扰：计分板队徽、角标、地板和广告分别标。
11. 裁判入场：脚在场内仍是裁判。
12. 球员遮挡：角色、真实ID和号码可读性分开。
13. 切镜：切镜边界与前后球/筐证据段。
14. 慢动作/重复回放：与原投篮对应的play_id。
15. OCR错误：真实读数，标数字不可读和易混淆字。
16. 比分更新延迟：过筐时刻与更新时刻。
17. 罚球：每次出手单独标，涵盖相邻两次罚球合并更新。
18. 短时间连续投篮：出手人/篮筐/轨迹分别记录，防止时间去重误合并。

## 4. 指标口径

- 球框：固定置信度、IoU≥.5一对一匹配（可并列IoU .3定位诊断），TP/FP/FN、Precision/Recall/F1。未完整帧不报整帧Precision；空分母为 null/尚不可计算。
- 球员 Recall：完整可见人员真值，按可见性分层；角色误纳率=被纳入的明确非球员/所有纳入人员；UNKNOWN独立报告。
- 轨迹中断：按同一人工球ID、同镜头可见连续段与预先固定最大间隔定义；预测点不能算真实检出，不跨遮挡/切镜偷接。
- 事件：复用 `eval_match_annotations.match_times` 最大化一对一时间匹配；精确时间容差预先固定±1.5秒，近似人工时间单独给区间诊断，不能混用。
- 命中 Precision/Recall：仅对去重后的真实出手与正确结果统计，UNKNOWN、回溯失败与多报分开；没有分数变化不算未中真值。
- 球员归属：有真实出手人标签的事件作为分母，未归属率同时报告；不挑掉未知事件制造高归属率。
- 性能：记录 GPU/驱动/torch、输入帧率/实际PTS/解码帧数、模型SHA、imgsz/conf、每阶段时间、ROI次数、显存；冷/热启动、并发与叠框/高光是否包含必须说明。
- 模块消融：使用同一冻结视频/标注/来源分组、同权重和基础参数，分别跑原始/过滤/追踪/两ROI/角色/OCR/回溯/完整组合。改变一个模块才能比较；当前步骤1、2尚未执行这些消融。

## 6. 2026-10-18 集中审核字段与隔离

第二阶段复用`serve_match_labeling.py`与`web/match-labeling.html`。集中六项任务记录原片/预览SHA、原片时间、解码帧时间依据与JPEG帧SHA；AV1原片用已登记H264转码预览，不声称逐像素一致。算法框位于独立`evidence*.json`，可切换原分析/640/1280，永不自动复制到`annotations.json`。

- `review.is_shot`、`is_replay`：pending/yes/no/unknown；`result`：pending/made/missed/unknown/not_applicable。无出手时不同时记命中。
- `review.release_interval`为原片秒的区间；每次确实发生的出手继续写入既有`shots[]`。分值、play_id、真实队名、球员/号码不确定时留未知；说明盖帽和后续回抛是否同一个动作。
- `review.status=completed`只表示人工核对完成，需审核人、明确判断及`shots_complete=true`；允许结论为未知。显式完成人工核对后写`review_status=human_completed`，草稿为`pending_human_review`；任何状态均固定`training_approved=false`，不自动批准训练。
- 保持`frames_complete`只表示篮球完整；新增`rims_complete`、`persons_complete`为各帧独立完整性。人员框`kind=person`及role只由人工填写，不能用tracker ID替代真实身份。
- `selection_reason`等属于阈值/NMS后的算法证据；未被YOLO输出不等于真实无球。审核指标必须以经复核的完整框/事件为分母。
- 同场剪辑、转码和回放按source_match_id归组；来源未确认的视频隔离在Development，禁止充作新独立测试。

### 部分审核与重复帧（2026-10-18补充）

默认只展示少量关键帧，完整原帧仍可切换。相似画面可跳过，记录`review_skip=redundant_or_not_reviewed`，球可见性保持pending；不能当无球、完整帧或训练背景。已标框独立保留，不传播到邻帧。只完成部分框不要求勾frames_complete；已确认出手记录可以先保存。抽样框只能用于对应审核帧的指标，不可外推整段Recall/轨迹完整性。
