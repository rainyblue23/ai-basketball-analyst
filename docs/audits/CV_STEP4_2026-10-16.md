# 步骤4：篮球候选、ROI与时序恢复

日期：2026-10-16。承接[基线](CV_BASELINE_2026-10-15.md)和[步骤3](CV_STEP3_2026-10-16.md)。

## 范围与当前结论

本轮沿用现有YOLO模型、LegacyShotStream、球的有界速度预测、两种ROI及投篮状态机。没有训练或切换线上权重，没有重启服务、覆盖用户任务或启用暂停中的记分牌改动。

**默认配置仍未解决两段开发视频的自动投篮漏检。** 增大补检频率并对低置信度候选作多帧确认后，Dairy短片产生1次命中事件；利拉德30秒片段仍0事件。该实验不作为默认配置。人员角色、完整离手状态机、OCR回溯与最终事件统计尚待后续阶段处理。

## 诊断与修改文件

| 问题 | 本轮处理 | 文件（位于src/aihoop） |
| --- | --- | --- |
| 人头误检使补检被提前跳过 | ROI前的preview与最终选择使用同一份person头部排除上下文；保留观众检测框作排除依据，不要求先成为场上球员 | `sources.py`、`legacy_shots/stream.py` |
| 镜头平移被直方图误报为切镜，清掉球与篮筐历史 | 仅对原算法报告的切镜，复用frame_motion的ORB/RANSAC复核；至少3个空间网格各有足够内点，固定角标本身不够。确认为新镜头仍清空历史 | `frame_motion.py`、`sources.py` |
| 整帧、不同尺度和ROI重复框没有统一来源/去重 | Det增加source、region、support_sources；先按球框IoU去重，保留最高原始置信度与来源，不把同帧不同裁剪当多帧证据。ROI只回映射一次，不混入rim或motion_ball | `legacy_shots/detector.py`、`ball_recovery.py`、`legacy_shots/stream.py` |
| 低分候选直接丢弃，或降低阈值就可能直接接受噪声 | 候选阈值与确认阈值分开；可选多帧确认要求至少3个独立时刻、有位移、尺寸/运动关联及近期球或新鲜篮筐上下文；preview不提交历史，切镜不借用上个镜头历史 | `legacy_shots/ball_selection.py`、`legacy_shots/stream.py`、`legacy_shots/settings.py` |
| 战术球轨迹与投篮球选择口径不同 | 专用模型可用的legacy模式默认只把最终选择的模型实测送入ball_cands；同帧至多一个，不把预测/运动块作为真实球输入战术。可关闭此策略做对照；没有专用模型时保留原COCO后备路径 | `sources.py` |
| ROI性能与候选结果难以复查 | 两个原开关保留；频率、最多两次裁剪和输入分辨率可配置；保存两种ROI审计、逐框来源、拒绝原因、frame_id/timestamp及镜头复核记录 | `ball_recovery.py`、`legacy_shots/stream.py`、`sources.py`、`legacy_shots/settings.py` |

新增 `scripts/benchmark_ball_recovery.py`，冻结模型/源码/配置，在隔离输出目录运行none、ball、rim、both四组。新增 `tests/test_ball_recovery_stage4.py`。既有 `tests/test_shot_night_settings.py` 的非法参数断言从ball_conf=.9改为1.1：.9现在是合法可配置值，仍测试越界拒绝。

没有新增第二套篮球追踪器、Kalman模块或模型实例；继续使用现有速度估计、运动门控、置信度/尺寸评分与失效上限。没有放宽接近篮筐、出手、穿筐或未中规则。

### 调用关系

`VideoSource.run → 整帧YOLO → LegacyShotStream.preview_ball → 必要时原多尺度/球ROI/筐ROI → deduplicate_candidates → LegacyShotStream.update → 原ScoreEngine`

`LegacyShotStream.update → 最终模型实测球 → 原ball_cands/轨迹/战术路径`

候选留在raw_track的legacy_shots.frames[].ball_candidates中。未通过候选仍有拒绝原因。预测标记measurement=false，不能刷新真实观测锚，也不能投票确认低分模型框。

## 配置

均通过现有 `legacy_detect` 接口传递；新增项由LegacyDetectOptions校验。

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| ball_conf | .25 | 单帧确认阈值；不会绕过尺寸/人头/UI/时序检查 |
| ball_candidate_conf | .25 | 候选检测下限；本轮实验.15，不改变默认值 |
| ball_low_conf_confirm | false | 允许低分模型框经多帧确认进入真实测量流 |
| ball_low_conf_min_frames | 3 | 独立帧数下限，允许3～10 |
| ball_low_conf_window_s | .25 | 确认窗口，上限1秒 |
| ball_low_conf_min_motion_px | 2 | 至少有实际位移；不是只靠圆形或颜色 |
| ball_low_conf_near_rim_widths | 3 | 无近期球时所需篮筐邻域，单位筐宽 |
| ball_low_conf_max_candidates | 16 | 每帧历史候选上限 |
| ball_candidate_nms_iou | .5 | 同帧跨尺度/ROI球候选去重阈值 |
| ball_track_selected_only | true | 专用模型可用时战术与事件共享最终真实球选择；false用于旧口径对照 |
| ball_roi_recovery / ball_rim_recovery | false / false | 原球预测ROI与筐ROI开关；保留默认 |
| ball_roi_max_per_frame | 2 | 两类ROI合计最多1～2次，未运行的裁剪不占次数 |
| ball_roi_retry_hz | 5 | 缺球重试频率；实验15Hz；整帧球检测仍逐帧运行 |
| ball_roi_imgsz / ball_rim_roi_imgsz | 640 / 960 | 原两种裁剪的YOLO输入尺寸 |
| scene_motion_guard | true | 复核直方图切镜误报；false恢复原切镜判断 |
| scene_motion_min_matches / min_ratio | 20 / .45 | 匹配数与内点率下限（两项均带scene_motion_前缀） |
| scene_motion_min_grid_cells / min_points_per_cell | 3 / 3 | 3×2画面网格的分布约束（均带scene_motion_前缀） |
| scene_motion_max_side | 640 | 仅复核时缩放图像的最大边 |

球ROI沿用有界预测区域（半径96～384px，随球尺寸和缺失间隔调整）；筐ROI沿用approach_radius_ratio×筐宽和最小96px，只围绕新鲜篮筐。固定UI、头部、上方无锚角标等原过滤保持。高弧线重捕仍可能被上方角标过滤阻断。

### 候选阈值与补检频率实验

配置：ball_candidate_conf=.15、ball_low_conf_confirm=true、ball_roi_retry_hz=15，两个ROI均开；ball_conf仍.25。

| 视频 | 模型观测帧 | 筐可用帧 | ROI调用（球/筐） | 事件 | 耗时 |
| --- | ---: | ---: | ---: | --- | ---: |
| Dairy | 289 | 835 | 142 / 249 | made 1 | 44.36s |
| Lillard | 151 | 161 | 128 / 52 | 0 | 33.87s |

Dairy的6.533s帧由置信度.217的实际模型球框补上，随后原状态机在7.033s输出一次命中。抽看对应视频可见实际投篮和入筐，联系图见dense_low目录的event_contact.jpg。该抽查不是整段逐帧/逐事件完整标注；该事件的release_t=5.1、player_binding=history及无标定时仍写points_verified的旧语义尚需步骤5检查，不能当作出手时间、出手人或2分已验收。

另做仅把重试频率改为15Hz、候选阈值保持.25的对照：Dairy为261个观测帧、1次unknown（7.3s）、41.15s；Lillard为134个观测帧、0事件、34.67s。与同频率的低阈值实验相比，Dairy原来unknown的事件变成made，说明需要关键帧真实模型证据，单纯增加搜索次数并不足够。仍需逐事件完整标注才能判断对错。

### 审核帧的低阈值风险检查

使用原11张完整审核帧，重新核对记录/图片SHA与基线一致，同一E-BARD模型SHA、imgsz640、IoU=.5，原始检测器结果如下。这里没有应用视频时序确认，因此不能拿它当最终选择器的P/R。

| 原始conf | TP | FP | FN | Precision | Recall | F1 | 3张负例中出现误检的帧数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| .25（原基线） | 3 | 4 | 5 | 42.86% | 37.50% | 40.00% | 0 |

## 风险、回退与下一步

预修改备份：`/data/projects/backups/cv-step4-20261016-115321/`。本轮差分与测试保存于 `out/cv_step4_20261016/`；实验目录保存冻结源码、模型SHA、配置、逐帧JSON及metrics，不用dirty HEAD冒充干净基线。不要对包含其他未提交工作的整个仓库作reset。算法对照可关闭scene_motion_guard、ball_track_selected_only与两个ROI；低阈值确认原本就是关闭的。

低阈值多帧确认仍可能接受移动背景误检；person头部排除仍可能挡住经过头部附近的真球；连续几何不等于可靠的回放/广告分类；球场标定缺失时无法验收热区和战术地面坐标；临时track ID不是跨镜头真实球员身份。

下一步：用原视频关键窗口核查离手、缺球后的中位数平滑与实际穿筐时间，检查历史出手人绑定、未经标定的分值标记；补齐比赛来源分离的事件/负例标注，再推进球员角色与球队时序分类。现有证据不足以立即训练新权重。
