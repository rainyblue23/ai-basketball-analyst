# 人工标注与自动评测

`ground_truth/match_testset_20261011.json` 保留用户标注的原片30–90秒范围、
原始归一化篮球框、出手记录与原文件SHA-256。原始标注不被自动结果覆盖。
第2段零出手由用户在聊天确认；第4段已更正为37秒2分未中。
四段合计4次出手、32帧：7帧球可见、19帧看不到球、6帧看不清。
先前使用情况未核实，因此当前不能称为独立测试集。

## 运行

在项目根目录、已配置Python依赖的环境中：

```
python scripts/eval_annotated_balls.py --batch out/match_testset_20261011 --weights runs/detect/ball/weights/best.pt --out out/match_testset_20261011/ball_evaluation.json
python scripts/eval_match_annotations.py --truth eval/ground_truth/match_testset_20261011.json --out out/match_event_evaluation
```

标注帧评测分别报告IoU≥0.5、IoU≥0.3与中心落框的宽松定位指标；
不把三种指标混为准确率。看不清帧排除，不可见帧报告有候选的帧数。
没有队标真值框，不能计算队标专项误检率。多尺度并集仅是诊断对照，
不是在线级联或时序选球的最终指标。

事件评测采用±1.5秒、按时间顺序一对一匹配，先最大化匹配数，
再最小化总时间误差。报告真实出手/引擎事件/确认命中数、漏检与多报。
为了精确截取时段，使用CRF18重编码，因此检测可能与原片有轻微差异。
默认不开球员、比分牌和自动标定；报告会记录参数。

## 篮球补查

常规候选是否可用，与最终时序选球使用同一套尺寸、图案与运动检查。
一个已被运动连续性拒绝的错误目标不能阻止多尺度补查。
`legacy_detect.ball_roi_recovery=true` 可试验局部复检，默认false。
它仅在近期实测轨迹存在、无切镜且常规检测失去目标时运行；
预测只限定搜索区域，返回的候选必须来自模型实测。裁剪框映射回原帧，
不把裁剪中的篮筐拿来替换整帧篮筐，不修改命中或计分规则。

现有开发视频7投3中检查中，开关两种设置的7条事件完全一致；
局部复检未证明收益，继续默认关闭。不能据此宣称召回提升。
